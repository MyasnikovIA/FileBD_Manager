## 1. Развёртывание сервера БД

Проект работает поверх **CouchDB-совместимого** сервера. Проще всего — `pouchdb-server` под Node.js.

### 1.1. Установка Node.js

**Linux (Ubuntu / Linux Mint):**

```bash
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt install -y nodejs build-essential erlang openssl curl git python3
node -v   # должно быть v20.x
npm -v
```

**Windows 10:** скачать LTS-установщик с <https://nodejs.org/en/download/> и установить.

### 1.2. Установка pouchdb-server

**Linux (глобально):**

```bash
sudo npm install -g pouchdb-server
which pouchdb-server    # /usr/local/bin/pouchdb-server
```

**Windows (локально в папке проекта):**

```bat
mkdir C:\PouchDB
mkdir C:\PouchDB\BD
cd C:\PouchDB
npm init -y
npm install pouchdb-server
```

### 1.3. Каталог для данных БД

**Linux:**

```bash
mkdir -p /home/myasnikovia/CouchDB
chmod 755 /home/myasnikovia/CouchDB
```

**Windows:**

```bat
mkdir C:\PouchDB\BD
```

### 1.4. Конфигурационный файл

**Linux — `/home/myasnikovia/.pouchdb-server/config.json`:**

```bash
mkdir -p ~/.pouchdb-server
cat > ~/.pouchdb-server/config.json << 'EOF'
{
  "httpd": { "port": 5984, "bind_address": "0.0.0.0" },
  "couchdb": { "database_dir": "/home/myasnikovia/CouchDB" },
  "cors": {
    "origins": "*",
    "credentials": true,
    "methods": "GET, PUT, POST, HEAD, DELETE, OPTIONS",
    "headers": "accept, authorization, content-type, origin, referer"
  }
}
EOF
```

**Windows — `C:\PouchDB\config.json`:**

```json
{
  "http": { "port": 5984, "host": "0.0.0.0" },
  "couchdb": { "dir": "C:/PouchDB/BD" },
  "cors": {
    "origins": "*",
    "methods": "GET, POST, PUT, DELETE, HEAD, OPTIONS",
    "headers": "accept, authorization, content-type"
  }
}
```

> ⚠️ **Про CORS.** Без `"origins": "*"` браузер заблокирует запросы к БД с другого origin, и приложение не подключится. Это обязательная настройка.

### 1.5. Запуск сервера

**Linux (вручную):**

```bash
pouchdb-server --config ~/.pouchdb-server/config.json
```

**Windows (вручную):**

```bat
cd /d C:\PouchDB
npx pouchdb-server --port 5984 --host 0.0.0.0 --dir C:\PouchDB\BD --config C:\PouchDB\config.json
```

Проверить, что сервер работает:

```
http://localhost:5984/_utils/
```

Откроется веб-интерфейс **Fauxton**.

### 1.6. Автозапуск (Linux, systemd)

Чтобы сервер поднимался при загрузке **до входа пользователя**:

```bash
sudo tee /etc/systemd/system/pouchdb-server.service > /dev/null << 'EOF'
[Unit]
Description=PouchDB Server
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=myasnikovia
Group=myasnikovia
WorkingDirectory=/home/myasnikovia
Environment=PATH=/usr/local/bin:/usr/bin:/bin:/usr/local/sbin:/usr/sbin:/sbin
ExecStart=/usr/local/bin/pouchdb-server --port 5984 --host 0.0.0.0 --dir /home/myasnikovia/CouchDB --config /home/myasnikovia/.pouchdb-server/config.json
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
EOF

sudo chown -R myasnikovia:myasnikovia /home/myasnikovia/CouchDB
sudo chown -R myasnikovia:myasnikovia /home/myasnikovia/.pouchdb-server

sudo systemctl daemon-reload
sudo systemctl enable pouchdb-server
sudo systemctl start pouchdb-server
sudo systemctl status pouchdb-server
```

> В `ExecStart` используйте **полный путь** к `pouchdb-server` (см. `which pouchdb-server`) и **полный путь** к `config.json` (`~` в systemd не раскрывается).

Открыть порт в firewall:

```bash
sudo ufw allow 5984/tcp
sudo ufw reload
```

### 1.7. Автозапуск (Windows, при входе в систему)

1. `Win + R` → `shell:startup`.
2. Положить туда файл `pouchdb-autostart.bat`:

```bat
@echo off
cd /d C:\PouchDB
start "PouchDB" /MIN cmd /c "npx pouchdb-server --port 5984 --host 0.0.0.0 --dir C:\PouchDB\BD --config C:\PouchDB\config.json"
```

### 1.8. Создание базы данных

Откройте **Fauxton** (`http://<хост>:5984/_utils/`) → **Databases** → **Create Database** → имя `FileBD` → **Create**.

Либо через `curl`:

```bash
curl -X PUT http://admin:password@localhost:5984/FileBD
```

### 1.9. Развёртывание веб-приложения

Скопировать содержимое папки проекта в корень Apache:

```
C:\Apache24\htdocs\filebd\
├── index.html
├── css\
├── js\
├── modals\
└── lib\
```

Открыть в браузере: `http://localhost/filebd/` — приложение заработает без дополнительных модулей Apache.

## 2. Установка подключения

### 2.1. Первый запуск

1. Откройте `http://<хост>/filebd/` в браузере.
2. Появится **модальное окно подключения**:
   - **Адрес БД (с портом)** — подставляется автоматически как `http://<ваш-хост>:5984`.
   - **Имя базы данных** — `FileBD`.
   - **Имя пользователя** — логин CouchDB (или пусто, если авторизация отключена).
   - **Пароль пользователя** — пароль CouchDB (или пусто).
   - **Режим работы** — `🗔 Панельный` (классический FAR) или `🖥 Оконный` (рабочий стол с окнами).
3. Нажмите **«Подключиться»**.

При успехе:
- в тулбаре появится статус **✅ Подключено: …**;
- откроются обе панели с корнем `/`.

### 2.2. Автоматическое переподключение

Данные подключения сохраняются в `localStorage` под ключом `filebd_conn`.

При следующем открытии страницы окно авторизации **не появится** — приложение сразу подключится к БД и восстановит последний путь/курсор в каждой панели.

### 2.3. Выход и смена пользователя

Нажмите **🔓 LogOut** в тулбаре. Данные подключения из `localStorage` будут удалены, панели сброшены в корень. Откроется окно подключения заново.

### 2.4. Мульти-БД: подключение каждой панели к своей базе

Каждая панель имеет **свой** контекст (`FAR.side.left`, `FAR.side.right`). Можно подключить их к разным БД — например, для копирования файлов между разными серверами CouchDB.

**Как переключить БД для одной панели:**

- **Клик по пути** в шапке панели (например, по `/img/2024`), или
- кнопка **🗄️** в шапке панели (ПКМ там же работает).

Откроется модалка подключения **только для этой панели**.

**Как подключить обе панели к одной БД:**

- Кнопка **🔐 LogIn** в тулбаре — открывает модалку сразу для двух панелей.

**Как скопировать/перенести между разными БД:**

- Выделить файлы в одной панели → **📋 → Копировать** или **✂️ → Перенести** → файлы попадут в БД второй панели.

### 2.5. Частые ошибки подключения

| Симптом | Причина | Решение |
|---|---|---|
| Не удалось подключиться (сеть/CORS) | Сервер не запущен, нет `origins: "*"`, firewall | Запустить сервер, проверить `config.json`, открыть порт 5984 |
| Неверный логин или пароль (401) | Опечатка или админа нет в БД | Проверить логин/пароль; подключиться без авторизации |
| База данных не найдена (404) | Опечатка в имени БД | Создать БД `FileBD` через Fauxton |

## 3. Настройка пользователей

Пользователи — стандартные администраторы CouchDB. Проект не хранит собственных учётных записей.

### 3.1. Где задаются пользователи

**Linux — в `~/.pouchdb-server/config.json`:**

```json
{
  "admins": {
    "MyasnikovIA": "-pbkdf2-<hash>..."
  }
}
```

**Windows — в `C:\PouchDB\config.json`:**

```json
{
  "admins": {
    "MyasnikovIA": "-pbkdf2-<hash>..."
  }
}
```

Ключ — имя пользователя, значение — **PBKDF2-хеш** пароля (не сам пароль).

### 3.2. Как добавить администратора

**Способ 1 — через Fauxton:**

1. Открыть `http://<хост>:5984/_utils/`.
2. Раздел **🔧 Setup → Configure a Single Node** (или **Security**).
3. Ввести логин/пароль → сохранить.

**Способ 2 — сгенерировать хеш:**

```bash
pouchdb-server --help    # посмотреть справку по генерации
```

Либо добавить админа через API:

```bash
curl -X PUT http://<хост>:5984/_config/admins/MyasnikovIA -d '"MyPassword"'
```

После перезапуска сервера запросы без авторизации будут отклоняться (401).

### 3.3. Как отключить авторизацию (для локальной сети)

Убрать блок `admins` из `config.json`, перезапустить сервер:

```bash
sudo systemctl restart pouchdb-server
```

Теперь подключение в модалке — с пустыми полями «Пользователь» и «Пароль».

### 3.4. Ограничение доступа к отдельной БД

CouchDB позволяет выдавать права на конкретную базу через `_security`:

```bash
curl -X PUT http://admin:pass@localhost:5984/FileBD/_security \
  -H "Content-Type: application/json" \
  -d '{
    "admins": { "names": ["MyasnikovIA"], "roles": [] },
    "members": { "names": ["user1", "user2"], "roles": [] }
  }'
```

- `admins` — кто может менять дизайн-документы и удалять БД.
- `members` — кто может читать/писать файлы.

### 3.5. Практика

- Храните **разные пароли** для админа CouchDB и для пользователей, которые подключаются через веб-приложение.
- CouchDB передаёт учётные данные по HTTP Basic Auth (base64). Для доступа через интернет обязательно используйте **HTTPS** (nginx/Apache как reverse-proxy).
- Проект **не шифрует** тела файлов в БД — это ответственность CouchDB (например, шифрование диска или SSL/TLS).

## 4. Поддерживаемые файлы

### 4.1. Любые файлы

Файловый менеджер хранит **произвольные бинарные данные** — это не ФС, а БД, поэтому ограничений на расширение нет. Загружайте что угодно: архивы, документы, базы данных, ROM-файлы, изображения и т.д.

### 4.2. Встроенные просмотрщики

Двойной клик по файлу в панели откроет подходящий просмотрщик:

| Тип | Расширения | Что происходит |
|---|---|---|
| **Изображения** | `jpg`, `jpeg`, `png`, `gif`, `webp`, `svg`, `bmp`, `ico` | Открываются как `<img>` |
| **Текст** | `txt`, `md`, `json`, `xml`, `csv`, `log`, `html`, `css`, `js`, `py`, `java`, `c`, `cpp`, `h`, `ini`, `cfg`, `yaml`, `yml` | Показывается в `<pre>` |
| **Бинарные** | любые остальные | Hex-превью первых 256 байт |
| **PDF** | `.pdf` (или `contentType: application/pdf`) | Через PDFObject |
| **Панорамы 360°** | `jpg/png/webp` с соотношением ≈ 2:1 | Pannellum |
| **MP3 / аудио** | `mp3`, `m4a`, `ogg`, `wav`, `flac`, `aac`, `opus` | Winamp-плеер |
| **Видео** | `mp4`, `webm`, `mkv`, `mov`, `m4v`, `ogv`, `avi` | HTML5 `<video>` c MSE |
| **DOS-игры** | `.jsdos` | js-dos эмулятор |
| **NES-игры** | `.nes` | jsnes эмулятор |
| **Другие эмуляторы** | `sfc, smc, z64, n64, gba, gb, nds, psx, cue, iso, md, sms, gg, pce, ngp, ws, col, d64, …` | EmulatorJS |

### 4.3. Навигация ◀ / ▶

Внутри **любого** просмотрщика доступны кнопки **◀** и **▶** в шапке — переключают на предыдущий/следующий файл **текущей папки**. Папки пропускаются.

### 4.4. Сохранение состояний эмуляторов

Для EmulatorJS есть отдельная подпапка `.saves/`:

```
/games/snes/doom.sfc
/games/snes/.saves/doom.state
```

Кнопки **Save State** / **Load State** внутри эмулятора сохраняют/читают состояние прямо в FileBD.

## 5. Просмотр фотографий 360°

### 5.1. Что считается панорамой

Панорама — это **equirectangular-изображение** с соотношением сторон **≈ 2:1** (например, 7744×3872, 4096×2048). Такие снимки делает большинство камер для панорам (`Insta360`, `Ricoh Theta`, `GoPro Max` и т.п.).

Приложение определяет панораму **автоматически** по соотношению сторон и открывает её в Pannellum, а не как обычную картинку.

### 5.2. Как открыть панораму

1. Загрузите `.jpg` (или `.png`/`.webp`) панораму в БД через панель (📤 Загрузить, либо drag&drop).
2. Двойной клик по файлу в панели — откроется окно просмотра панорамы.
3. Внутри:

   - **Мышь** — круговой обзор.
   - **Колёсико** — приближение / отдаление.
   - **Кнопки ◀ / ▶** в шапке — переключение на предыдущий/следующий файл папки.
   - **✏️ Редактор точек** — открыть редактор хотспотов (см. раздел 6).
   - **📥 Скачать оригинал** — сохранить файл локально.
   - **Двойной клик по панораме** — открыть редактор с координатами, куда вы кликнули.

### 5.3. Обзор с клавиатуры

| Клавиша | Действие |
|---|---|
| `←` / `→` | Поворот по горизонтали |
| `↑` / `↓` | Поворот по вертикали |
| `+` / `-` | Приближение / отдаление |
| `Esc` | Закрыть просмотрщик |

### 5.4. Оконный режим

Если вы работаете в оконном режиме (**🖥 Рабочий стол**), панорама откроется в отдельном окне WM, которое можно перетаскивать, разворачивать и пристыковывать к краям экрана. При переключении ◀ / ▶ новое окно унаследует размер и позицию предыдущего.

## 6. Установка точек перехода по фотографиям 360°

**Точка перехода (hotspot)** — это активная зона на панораме, клик по которой переводит на другую панораму (или показывает информацию).

### 6.1. Где хранятся точки перехода

Точки перехода хранятся в **JSON-файле рядом с панорамой**:

```
/img/2024/room.jpg
/img/2024/room.json   ← здесь лежат hotSpots, pitchCam, yawCam
```

Имя JSON совпадает с именем изображения (без расширения). Если JSON нет — панорама открывается без хотспотов.

**Формат JSON:**

```json
{
  "pitchCam": -5.5,
  "yawCam": 12.3,
  "hotSpots": [
    {
      "id": 1700000000000,
      "name": "Кухня",
      "type": "scene",
      "text": "Перейти на кухню",
      "pitch": -12.5,
      "yaw": 45.0,
      "targetPitch": -5.0,
      "targetYaw": 90.0,
      "source": "db",
      "dbPath": "/img/2024/kitchen.jpg",
      "panorama_url": "img/2024/kitchen.jpg",
      "createdAt": "2024-01-01T00:00:00.000Z"
    }
  ]
}
```

- `source: "db"` — цель ищется в FileBD по `dbPath`.
- `source: "url"` — цель загружается по внешнему URL (`panorama_url`).

### 6.2. Создание точки: пошагово

**Шаг 1 — откройте панораму.**

В панели FAR двойным кликом откройте панораму `.jpg` (или `.png`). Она откроется в модалке Pannellum (или в WM-окне).

**Шаг 2 — откройте редактор точек.**

Два способа:

- Нажмите кнопку **✏️ Редактор точек** в футере.
- Либо **двойной клик по самой панораме** в нужном месте — откроется редактор, а координаты клика (Yaw/Pitch) уже будут подставлены в форму.

**Шаг 3 — заполните поля в форме «Точка перехода» (левая колонка).**

| Поле | Что вводить |
|---|---|
| **Название** | `Кухня` (произвольное) |
| **Тип** | `Сцена (переход)` или `Информация` |
| **Текст подсказки** | `Перейти на кухню` (показывается при наведении) |
| **Yaw** / **Pitch** | Куда «прицепить» точку на **текущей** панораме. Двойной клик подставит автоматически |
| **Путь к файлу в БД** | `/img/2024/kitchen.jpg` — целевая панорама в FileBD. Кнопка **📁 Обзор** открывает диалог выбора |
| **Или URL** | `https://…` — если цель вне БД |
| **Target Yaw / Target Pitch** | Куда будет смотреть камера после перехода |

**Шаг 4 (опционально) — предпросмотр целевой сцены.**

Правая колонка:

- Кнопка **👁 Загрузить предпросмотр** — загрузит целевую панораму в миниатюру.
- Покрутите мини-панораму в нужное положение.
- Кнопка **🎯 Зафиксировать направление** — запишет текущий угол камеры в поля **Target Yaw / Target Pitch**.
- Кнопка **↺ Сбросить направление** — обнулит Target.
- Кнопка **🎥 Сбросить вид** — вернёт камеру мини-панорамы в 0°, 0°.

**Шаг 5 — сохраните точку.**

Кнопка **💾 Сохранить точку**. Точка появится в списке «Точки перехода на текущей панораме» (внизу правой колонки).

### 6.3. Управление созданными точками

В списке хотспотов справа доступны три кнопки для каждой точки:

| Кнопка | Действие |
|---|---|
| 🔍 | Загрузить точку в предпросмотр — открыть целевую сцену и посмотреть на неё с заданным углом |
| ✏️ | Редактировать — загрузить точку в форму, изменить поля, снова **💾 Сохранить точку** |
| 🗑️ | Удалить — с предварительным подтверждением |

### 6.4. Сохранение JSON

Точки перехода хранятся в JSON-файле рядом с панорамой. Для сохранения:

**Шаг 6 — экспорт.**

Нажмите кнопку **📤 Экспорт JSON** в левой колонке.

JSON сохранится в БД рядом с текущей панорамой:

```
/img/2024/room.jpg
/img/2024/room.json     ← создан/обновлён
```

Панель FAR автоматически перечитается, и вы увидите новый `.json` в списке.

**Импорт из локального файла:**

Кнопка **📥 Импорт JSON** — читает `.json` с вашего компьютера (например, для массового переноса хотспотов между панорамами).

### 6.5. Проверка работы переходов

1. Закройте редактор (**✕** в шапке или **Esc**).
2. Вернитесь в панель просмотра панорамы.
3. Наведите мышь на появившуюся точку (например, «Кухня») — курсор станет «указателем», появится подсказка.
4. **Кликните по точке** — приложение найдёт целевую панораму по `dbPath`, загрузит её, сбросит вид на указанный Target Yaw/Pitch и синхронизирует выделение в панели FAR.

### 6.6. Полезные советы

- **Точки перехода удобнее расставлять при ровном горизонте** — так Pitch целей будет «естественным».
- **Двойной клик по панораме** — самый быстрый способ задать Yaw/Pitch для новой точки: кликнули в нужное место — редактор уже открылся с координатами.
- **Target Yaw** — это угол поворота камеры после перехода. Если не задать, приложение поставит `0, 0`.
- **Проверяйте `source: "db"` и `dbPath`** — если целевая панорама переехала (или была переименована), переход сломается. После изменения путей через **🩹 Fix paths** не забудьте пересохранить JSON.
- **Несколько панорам подряд** — обойдите все панорамы объекта, создайте JSON в каждой, а точки перехода в одной ссылайте на другие. Получится интерактивная виртуальная прогулка.
- **Если Pannellum падает** — откройте JSON и убедитесь, что у каждого хотспота с `type: "scene"` есть либо `dbPath`, либо `panorama_url`. Точки без источника отбрасываются автоматически.
