# FileBD Manager — FAR-подобный менеджер файлов на PouchDB

Веб-приложение для управления файлами и папками, которые хранятся в
CouchDB-совместимой базе данных (PouchDB Server). Интерфейс сделан в стиле
двухпанельного файлового менеджера (как Norton Commander / FAR): слева и справа
— две независимые панели с текущими путями, между ними выполняются операции
копирования, переноса, удаления, скачивания и загрузки.

Проект специально разбит на модули (CSS, JS, HTML-фрагменты модальных окон),
чтобы его можно было легко дорабатывать без сборщиков и транспайлеров.

## Что делает проект

Это **веб-файловый менеджер**, работающий поверх CouchDB-совместимого сервера
(PouchDB Server). Вместо файловой системы файлы и папки хранятся как документы
в базе данных:

- **Папка** — документ с `_id = "d:<путь>"`, `type: "folder"`, полем `path`.
- **Файл** — документ с `_id = "f:<путь>"`, `type: "file"`, полем `path`,
  метаданными (`size`, `mtime`, `contentType`, `binary`) и прикреплённым
  вложением `b`, в котором лежат байты файла.

Приложение не требует никакой серверной логики — это чисто статический
HTML/JS/CSS, который общается с БД напрямую через REST-API CouchDB/PouchDB.

Дополнительно реализован **встроенный набор просмотрщиков**, работающий с
файлами прямо из БД, без предварительного скачивания: изображения, текст,
PDF, панорамы 360° (Pannellum), игры для DOS (js-dos), NES (jsnes) и других
систем (EmulatorJS).

## Возможности

### Файловый менеджер

- 📁 Две независимые панели (левая/правая) с собственным текущим путём.
- 🗄️ **Мульти-БД**: каждая панель может быть подключена к своей CouchDB-базе.
- 📤 Загрузка файлов и целых папок (drag&drop из Проводника Windows).
- 📁 Создание папок.
- 📋 Копирование и ✂️ перенос файлов между панелями (в т.ч. между разными БД).
- 🗑️ Удаление файлов и папок (с содержимым).
- 📥 Скачивание выделенных файлов по отдельности.
- 🗜️ Скачивание файлов и папок одним ZIP-архивом (через JSZip).
- 🔍 Debug-окно со сводкой по типам документов в БД.
- 🩹 Миграция старых документов с ведущим слэшем в `path`.
- 🔐 Кнопка LogIn/LogOut: автоподключение по сохранённым данным.
- 💾 Подключение к произвольной CouchDB-совместимой БД с сохранением в `localStorage`.
- 🎨 Тёмная тема Catppuccin Mocha, адаптивная вёрстка.
- 🖱️ Контекстное меню (ПКМ) для файлов, папок и пустого места панели.

### Просмотрщики

- 👁️ Универсальный просмотрщик: изображения, текст, hex-превью для бинарных.
- 🌐 **Панорамы 360°** через Pannellum с поддержкой точек перехода.
- ✏️ **Редактор точек перехода** для панорам (экспорт/импорт JSON).
- 📄 PDF через PDFObject.
- 🕹️ **js-dos** (.jsdos) — DOS-игры.
- 🎮 **NES** (.nes) через jsnes.
- 🕹️ **EmulatorJS**: SNES, N64, PSX, GBA, GB, SMD, SMS, PCE, NGP, WS и др.,
  с сохранением состояний прямо в FileBD.
- ◀ ▶ Навигация по файлам панели прямо из просмотрщика.

### Управление с джойстика

- 🎮 Навигация по панелям, эмуляция клавиш, настройка маппинга через модалку.
- Три режима: **Файлы**, **Клавиши**, **Файлы + Клавиши**.

### Горячие клавиши

- ⌨️ F5, F6, F7, F8, Ctrl+A, Ctrl+Insert, Esc, стрелки, PgUp/PgDn, Home/End, Enter, Backspace.

## Требования

- **Сервер БД:** Node.js (для `pouchdb-server`) + PouchDB Server — устанавливается
  на Windows 10 / Linux / macOS.
- **Веб-сервер для статики:** любой Apache (или nginx, или даже `python -m
  http.server`) — но проект специально сделан так, чтобы **работать на голом
  Apache без правок конфига**.
- **Клиент:** современный браузер (Chrome, Firefox, Edge, Safari).

## Развёртывание PouchDB Server на Windows 10

### 1. Установить Node.js

Скачать и установить LTS-версию: <https://nodejs.org/en/download/>

Проверить в `cmd`:

```bat
node -v
npm -v
```

### 2. Создать папку для PouchDB и инициализировать проект

```bat
mkdir C:\PouchDB
mkdir C:\PouchDB\BD
cd C:\PouchDB
npm init -y
npm install pouchdb-server
```

### 3. Создать файл конфигурации `C:\PouchDB\config.json`

```json
{
  "http": {
    "port": 5984,
    "host": "0.0.0.0"
  },
  "couchdb": {
    "dir": "C:/PouchDB/BD",
    "uuid": "95c6d9ec-fd98-4af8-8641-7757a93403a9"
  },
  "cors": {
    "origins": "*",
    "methods": "GET, POST, PUT, DELETE, HEAD, OPTIONS",
    "headers": "accept, authorization, content-type"
  },
  "log": {
    "level": "info",
    "file": "C:/PouchDB/pouchdb-server.log"
  },
  "admins": {
    "MyasnikovIA": "XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX"
  }
}
```

> ⚠️ **Важно.** В разделе `admins` ключ — имя администратора, а значение — хеш
> пароля в формате, который понимает `pouchdb-server`. Готовый хеш выше — из
> примера. Если хотите сменить логин/пароль, проще всего временно убрать блок
> `admins`, запустить сервер без авторизации, а затем задать админа через
> `_utils` (Fauxton) или сгенерировать хеш утилитой
> `npx pouchdb-server --help` → генерация пароля. Значение
> `-pbkdf2-...` — это сериализованный PBKDF2-хеш (пароль `XXXXXXXX` из
> исходного проекта).

### 4. Запустить сервер (вручную, для проверки)

```bat
cd /d C:\PouchDB
npx pouchdb-server --port 5984 --host 0.0.0.0 --dir C:\PouchDB\BD --cors --config C:\PouchDB\config.json
```

В логе должно появиться что-то вроде `PouchDB Server listening on 5984`.
Проверьте в браузере: <http://192.168.15.20:5984/_utils/> — откроется Fauxton.

### 5. Запустить сервер в фоне (при старте Windows)

```bat
cd /d C:\PouchDB
start "PouchDB" /MIN cmd /c "npx pouchdb-server --port 5984 --host 0.0.0.0 --dir C:\PouchDB\BD --cors --config C:\PouchDB\config.json"
```

Команда `start /MIN` запускает свёрнутое окно `cmd`, в котором живёт сервер.
Чтобы PouchDB поднимался автоматически при входе в систему:

1. Нажмите `Win+R` → `shell:startup`.
2. Положите в открывшуюся папку `.bat`-файл с содержимым из шага 5.
3. Сохраните под именем `pouchdb-autostart.bat`.

При следующем входе сервер запустится сам.

### 6. Проверить, что база данных `FileBD` создана

Откройте Fauxton: <http://192.168.15.20:5984/_utils/> → **Databases** →
**Create Database** → имя `FileBD` → **Create**.

Либо через `curl`:

```bat
curl -X PUT http://USERNAME:XXXXXXXX@192.168.15.20:5984/FileBD
```

## Развёртывание веб-приложения на Apache

Проект — набор статических файлов, поэтому разворачивается тривиально.

### 1. Скопировать файлы

Положите содержимое папки `filebd-manager/` в корень веб-сервера Apache,
например:

```
C:\Apache24\htdocs\filebd\
├── index.html
├── css\
├── modals\
├── js\
└── lib\
```

### 2. Открыть в браузере

```
http://localhost/filebd/
```

Никаких дополнительных модулей Apache (SSI, mod_rewrite) включать **не нужно**.
Если Apache уже настроен и отдаёт статику — проект заработает как есть.

### 3. (Опционально) Доступ по сети

Если Apache слушает `0.0.0.0:80`, то же приложение будет доступно из локалки:

```
http://192.168.15.20/filebd/
```

Убедитесь, что PouchDB Server тоже слушает `0.0.0.0:5984` и в `config.json`
включён CORS (`"origins": "*"`). Иначе браузер заблокирует запросы
`fetch`/XHR к другому origin.

> **Про авторизацию.** Логин/пароль CouchDB (`USERNAME` / `PASSS`) защищают
> доступ к серверу БД. Никаких дополнительных ключей шифрования проект не
> использует — тела файлов и метаданные хранятся в БД открыто (либо в виде
> вложения `b`, либо в виде открытых чанков).

## Первый запуск и подключение

1. Откройте приложение в браузере.
2. Появится **модальное окно подключения**:
   - **Адрес БД (с портом)** — по умолчанию подставляется текущий хост +
     `:5984`, т.е. `http://<ваш-хост>:5984`.
   - **Имя базы данных** — `FileBD`.
   - **Имя пользователя** — `USERNAME`.
   - **Пароль пользователя** — `PASSS` (или ваш, если меняли админа).
3. Нажмите **«Подключиться»**.

Данные подключения сохранятся в `localStorage` под ключом `filebd_conn`.
При следующем открытии страницы окно авторизации **не появится** — приложение
сразу подключится к БД.

Чтобы **выйти** и очистить сохранённые данные — нажмите кнопку
**🔓 LogOut** в тулбаре. Откроется то же окно подключения, данные из
`localStorage` будут удалены.

## Мульти-БД: две независимые панели

Начиная с этой версии каждая панель может быть подключена **к своей
собственной базе данных**. Это позволяет, например, копировать файлы между
двумя разными CouchDB-серверами или между двумя БД на одном сервере.

### Как это работает

- В левой и правой панели хранится собственный контекст: `FAR.side.left` и
  `FAR.side.right` — каждый со своим `db`, `conn` (адрес, имя БД, логин,
  пароль), `path`, `fileIndex`, курсором и выделением.
- Подключение одной панели **не влияет** на другую.
- Копирование и перенос между панелями работают как в одной БД, так и между
  разными — модуль `35c-multi-db-transfer.js` сам определяет, совпадают ли
  `fullUrl` панелей, и выбирает нужный алгоритм.

### Как переключить БД для одной панели

- **Клик по пути** в шапке панели (например, по `/img/2024`) — откроет модалку
  подключения **только для этой панели**.
- Или **ПКМ → 🗄️** в шапке панели — то же самое.

### Как подключить обе панели к одной БД

- Кнопка **🔐 LogIn** в тулбаре — открывает модалку для **обеих** панелей
  одновременно.

### Хранение данных подключения

- Глобальные данные: `localStorage['filebd_conn']` (для обеих панелей).
- Для конкретной панели: `localStorage['filebd_conn_left']` /
  `localStorage['filebd_conn_right']`.

| Клавиша | Действие |
|---|---|
| `F5` | Обновить список файлов |
| `F6` | Перенести выделенное в другую панель |
| `F7` | Создать папку |
| `F8` или `Delete` | Удалить выделенное |
| `Ctrl + A` | Выделить всё в активной панели |
| `Ctrl + Insert` | Копировать выделенное в другую панель |
| `↑` / `↓` | Перемещение курсора |
| `PgUp` / `PgDn` | На страницу вверх/вниз |
| `Home` / `End` | В начало/конец списка |
| `Enter` | Войти в папку / открыть файл |
| `Backspace` | На уровень вверх |
| `Esc` | Закрыть просмотрщик / модалку |

## Просмотрщики файлов

Все просмотрщики открываются **двойным кликом** по файлу в панели. Внутри
каждого просмотрщика доступна навигация по файлам текущей панели через
кнопки **◀ / ▶** — папки при навигации пропускаются.

### Универсальный просмотрщик

Открывается для любых файлов, которые не подошли под специализированные
просмотрщики:

- **Изображения** (`jpg`, `jpeg`, `png`, `gif`, `webp`, `svg`, `bmp`, `ico`) —
  показываются как `<img>`.
- **Текст** (`txt`, `md`, `json`, `xml`, `csv`, `log`, `html`, `css`, `js`,
  `py`, `java`, `c`, `cpp`, `h`, `ini`, `cfg`, `yaml`, `yml`) — показывается
  в `<pre>`.
- **Бинарные** — hex-превью первых 256 байт.

### PDF

Файлы `.pdf` (или с `contentType: application/pdf`) открываются через
**PDFObject**. Если браузер не умеет встраивать PDF inline — предлагается
скачать файл.

### Панорамы 360°

См. отдельный раздел ниже.

### js-dos (.jsdos)

DOS-игры открываются через **js-dos**. Управление клавиатурой передаётся
внутрь эмулятора.

### NES (.nes)

NES-игры открываются через **jsnes** (библиотека подгружается динамически
через Blob URL — чтобы обойти CommonJS-обёртку UMD). Управление:
стрелки, `Z` — B, `X` — A, `Enter` — Start, `Right Ctrl` — Select.

### EmulatorJS

Поддерживаются SNES, N64, PSX, GBA, GB, SMD, SMS, PCE, NGP, WS, C64, Lynx,
Jaguar, Atari 2600/7800, NeoGeo Pocket, WonderSwan и др. — в зависимости
от расширения файла. Ядро подбирается автоматически по таблице
`FAR.EMULATOR_EXT_TO_CORE`.

**Сохранение состояний в FileBD**: модуль `32-emulator-state-db.js`
перехватывает события `saveState` / `loadState` и сохраняет/читает состояние
рядом с ROM — в подпапке `.saves/` с расширением `.state`.

## Панорамы 360°

### Просмотр

Панорамой считается изображение с соотношением сторон **≈ 2:1**
(например, 7744×3872). Определение автоматическое — при попытке открыть
файл через `FAR.isPanorama`.

Просмотр реализован на **Pannellum 2.5.6**. Внутри модалки доступны:

- кнопки ◀ ▶ для навигации по файлам панели;
- кнопка «✏️ Редактор точек» — открывает редактор точек перехода;
- кнопка «📥 Скачать оригинал»;
- **двойной клик по панораме** — открывает редактор с координатами клика.

### Точки перехода (hotspots)

Точки перехода хранятся в **JSON-файле рядом с панорамой**:

```
/img/2024/room.jpg
/img/2024/room.json   ← здесь лежат hotSpots, pitchCam, yawCam
```

Формат JSON:

```json
{
  "pitchCam": -5.5,
  "yawCam": 12.3,
  "hotSpots": [
    {
      "id": 1700000000000,
      "name": "Кухня",
      "type": "scene",
      "text": "Перейти на кухню",
      "pitch": -12.5,
      "yaw": 45.0,
      "targetPitch": -5.0,
      "targetYaw": 90.0,
      "source": "db",
      "dbPath": "/img/2024/kitchen.jpg",
      "panorama_url": "img/2024/kitchen.jpg",
      "path": "",
      "createdAt": "2024-01-01T00:00:00.000Z"
    }
  ]
}
```

Поля:

- `source: "db"` — цель ищется в FileBD по `dbPath`;
- `source: "url"` — цель загружается по внешнему URL из `panorama_url`.

### Редактор точек перехода

Открывается из просмотрщика панорам кнопкой «✏️ Редактор точек» или двойным
кликом по панораме.

Возможности:

- создание/редактирование/удаление точек;
- выбор целевой сцены из FileBD через **модалку выбора файла** (кнопка
  «📁 Обзор»);
- либо указание внешнего URL;
- предпросмотр целевой сцены на мини-панораме;
- фиксация направления взгляда после перехода (кнопка
  «🎯 Зафиксировать направление»);
- экспорт JSON (сохраняется **рядом с текущей панорамой в БД**);
- импорт JSON из локального файла.

### Навигация по хотспотам

Клик по хотспоту **в панели просмотра панорамы**:

1. если `source === 'db'` — файл ищется в БД по `dbPath`, читается, открывается
   как новая панорама;
2. если `source === 'url'` — файл ищется в текущей БД по `panorama_url`,
   затем открывается.

Защита от двойного клика: флаг `FAR._panoNavigating`.

## Формат данных в БД

Каждый файл/папка — отдельный документ CouchDB.

### Папка

```json
{
  "_id": "d:Documents/Projects",
  "type": "folder",
  "path": "Documents/Projects",
  "name": "Projects",
  "mtime": 1700000000000
}
```

### Файл (современный формат)

```json
{
  "_id": "f:Documents/Projects/readme.md",
  "type": "file",
  "path": "Documents/Projects/readme.md",
  "name": "readme.md",
  "size": 1234,
  "mtime": 1700000000000,
  "binary": false,
  "contentType": "text/markdown",
  "_attachments": {
    "b": {
      "content_type": "text/markdown",
      "length": 1234,
      "stub": true
    }
  }
}
```

Содержимое файла — во вложении `b`. Путь `path` — **без ведущего слэша**
(нормализуется функцией `FAR.normPath`). Все ID кодируются через
`encodeURIComponent`, поэтому слеши в путях безопасны.

### Файл (устаревший формат, чанки)

Если у документа **нет** вложения `b`, но есть поле `children` (массив ID
дочерних документов), тело собирается из вложений `b` этих чанков:

```json
{
  "_id": "f:legacy/big.bin",
  "type": "file",
  "path": "legacy/big.bin",
  "size": 10485760,
  "contentType": "application/octet-stream",
  "binary": true,
  "children": [
    "f:legacy/big.bin.chunk.0000",
    "f:legacy/big.bin.chunk.0001"
  ]
}
```

Чанки читаются как есть, без шифрования (шифрование из проекта удалено).

### Состояния эмулятора

Файлы `.state` сохраняются EmulatorJS рядом с ROM:

```
/games/snes/doom.sfc
/games/snes/.saves/doom.state
```

## Частые проблемы

### «Не удалось подключиться (сеть/CORS)»

- PouchDB Server не запущен. Проверьте: <http://192.168.15.20:5984/>.
- В `config.json` в блоке `cors` нет `"origins": "*"` — браузер блокирует
  запросы с другого origin.
- Вы обращаетесь к приложению по `http://`, а PouchDB — по `https://` (или
  наоборот). Смешанный контент браузер не пропустит.
- Файрвол Windows блокирует порт 5984. Разрешите входящие подключения
  для `node.exe`.

### «Неверный логин или пароль (401)»

- Опечатка в имени пользователя или пароле.
- В `config.json` секция `admins` пустая, а вы вводите логин/пароль. Уберите
  логин/пароль в модалке, чтобы подключаться без авторизации.

### «База данных не найдена (404)»

- Опечатка в имени БД в модалке (должно быть `FileBD`).
- База не создана. Создайте её через Fauxton или `curl -X PUT`.

### Файлы не появляются после загрузки

- Нажмите «🔄 Обновить» — иногда CouchDB возвращает индекс с задержкой.
- Проверьте `Debug` — есть ли ваши документы в БД.
- Если пути были с ведущим слэшем (старые данные) — нажмите
  «🩹 Fix paths».

### Ошибка при скачивании старого файла

- Документ старого формата, но в `children` нет ни одного доступного чанка.
  Проверьте, что все дочерние документы на месте и что у них есть
  вложение `b`.

### Панорама не открывается или падает Pannellum

- Проверьте, что в JSON хотспота у `type: "scene"` есть либо `panorama_url`,
  либо `dbPath`. Хотспоты без источника отбрасываются автоматически.
- Если панорама грузится из Blob URL — убедитесь, что у неё **не**
  задан `crossOrigin: 'anonymous'` (обёртка убирает его автоматически,
  но при ручной подстановке конфига это важно).

### Эмулятор не запускается

- Проверьте консоль браузера: если видите `Identifier 'EJS_STORAGE' has
  already been declared` — значит `loader.js` EmulatorJS загружен дважды.
  Обёртка `FAR._loadEmulatorLoader` это предотвращает, но ручная вставка
  `<script>` в обход модуля сломает запуск.
- Для NES: `jsnes.min.js` должен лежать в `lib/js-nes/`. Если библиотека
  не загружается, проверьте, что в `lib/js-nes/` нет `module.js` или
  `exports.js` — они могут перехватить UMD-ветку.

## Доработка проекта

### Добавить новую операцию

1. Создайте `js/NN-myop.js`, добавьте функцию в `FAR.myOp = function() {...}`.
2. Подключите файл в `index.html` **до** `23-main.js`.
3. Если операция — кнопка, добавьте `<button onclick="FAR.myOp()">…</button>`
   в тулбар.
4. Готово.

### Добавить новое модальное окно

1. Создайте `modals/my-modal.html` с разметкой.
2. В `js/23-main.js` в массиве `files` функции `FAR.injectModals` добавьте
   путь `'modals/my-modal.html'`.
3. Стили положите в `css/modal.css` или отдельный файл + `<link>` в
   `index.html`.

### Добавить колонку в панель

1. Правьте `FAR._renderPanelDOM` в `js/08-panels.js` — генерируйте свою
   разметку `.file-item`.
2. При необходимости добавьте данные в `fileIndex` в `js/06-files.js`
   (при загрузке директории).

### Добавить поддержку нового эмулятора

1. Найдите ядро EmulatorJS для нужной системы.
2. Добавьте расширение → ядро в таблицу `FAR.EMULATOR_EXT_TO_CORE` в
   `js/30-emulator-viewer.js`.

### Добавить новый тип просмотрщика

1. Создайте `js/NN-my-viewer.js` с функциями `FAR.isMyType(item)` и
   `FAR.openMyViewer(item, side)`.
2. В `js/11-viewer.js` в `FAR.openFile` добавьте проверку
   `if (FAR.isMyType(item)) { await FAR.openMyViewer(item, side); return; }`.
3. Создайте `modals/my-viewer.html` и подключите в `js/23-main.js`.
4. Стили положите в `css/my-viewer.css`.

### Расширить формат хотспота панорамы

1. Правьте `FAR._jsonToPannellumHotspots` и `FAR._peNormalizeHotspot`
   в `24-panorama-viewer.js` и `26-panorama-editor.js`.
2. Правьте экспорт в `FAR.peExportJson`.
3. Обновите формат в этом README (раздел «Панорамы 360°»).
